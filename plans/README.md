This currently makes 3 tooltip tests fail with `TypeError: tooltip.setHtml is not a function`, which makes `pnpm test` (and therefore `pnpm check` and every CI run) red until 003 lands. Verify order:
  1. `003` (tipviz v3 migration) — unblocks the test suite.
  2. `001` (verification baseline) — adds CI only AFTER `pnpm check` is green.
  3. `002` (strict characterization) — pins the now-green behavior so subsequent fixes are safe.
- 002 before all defect fixes (004–008): the characterization suite is the behavior contract that makes fixes safe. Fix plans flip their `it.todo` markers (004→plan-004 markers, 005→plan-005 markers) from red to green.
- 003 before 005: both edit `tooltip.mts`; migrate the API first, then fix the listener leak on the migrated code.
- 004 before 007 (extent cache) and 010 (e2e): the e2e harness asserts the empty-data guard in a real browser.
- 009 before 012/013: both designs build on the consolidated axis renderer and the safety net of 002.
- 011 can run any time after 001; it touches only config/scripts.
- 012 and 013 are design/spike plans — their deliverable is a document plus a throwaway branch, and each seeds a future numbered build plan.
